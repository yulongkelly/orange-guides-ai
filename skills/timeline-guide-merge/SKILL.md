# 时间线攻略合并

把多个来源的攻略合并成一份能边玩边看的时间线。这个技能由主会话核对，由子任务完成整理。

- “子任务”指你所用工具里能另开上下文干活的东西：子代理（subagent）、另开的会话或线程都可以。没有这类功能时，主会话自己按同样的读法和台账做，见第 4 步。
- 下文命令里的 `<本技能目录>` 指这份 SKILL.md 所在的文件夹。`python` 不可用时换成 `python3`。

## 流程

1. **确认输入。** 需要：来源文件、要整理的范围（比如“凡人期”）。
   - 范围没说时，先列出来源里出现的阶段，再让用户选。
   - 输出文件名默认 `<作品名>-<范围>时间线攻略.md`，不单独询问。
   - 时间单位跟随来源，不默认按月：按周、按月、按事件节点都可以，同一份里可以混用。
   - 涉及花数、数值规划时，提醒用户提供商城或版本截图，这些信息通常不在评论里。
   - 请用户提供一张游戏截图，确认屏幕上的时间格式。一张就够：其他时段的关键词按这个格式推出默认值，不留空，也不要求每个阶段都有截图。
2. **先查覆盖面。** 列出来源里的作者和条数。用户点名的作者或攻略，先在来源里搜索标题和关键词。搜不到就告诉用户“这篇不在数据里”，不要当作已覆盖。
3. **准备数据。** HTML 导出运行脚本，得到带编号、作者、日期、标签的记录 JSON（来源文件不可信，所以用 `-I`）：

   ```bash
   python -I -X utf8 <本技能目录>/scripts/prepare_records.py <来源.html> <records_clean.json>
   ```

   脚本会清理页面文字、按作者加发布时间（到分钟）去重、比对被删的副本，并打印报告。解析不到记录时会报错退出，说明格式与脚本不符，改由主会话手工切分，或调整脚本顶部的匹配规则。JSON 等其他格式不需要脚本，但同样要核对条数。

   人工看一遍报告，再往下走：
   - 声明条数、解析条数、保留条数是否对得上，被跳过的卡片是否确实不是帖子。
   - 作者分布有没有异常，例如某个“作者”其实是页面按钮，或同一人用了不同写法。
   - 去重结果和“需人工核对的被删副本”，有疑问的回到来源看。
   - 标签分布。标签（攻略、长评、同人、问答、提到改版）只是启发式提示，发给任务时说明由它复核。

   然后把记录切成定长分段，任务只读这些分段，不自己切：

   ```bash
   python -I -X utf8 <本技能目录>/scripts/split_records.py <records_clean.json> <工作目录>/data/chunks --chars 30000
   ```

   分段、笔记、台账都放在工作目录下，任务会话读写不到主会话的临时目录。
4. **按数据量安排任务。** 一个任务读得完的上限按约 15 万字算（约 5 份分段）。

   **为什么要这样安排。** 曾经有一次，47 万字的数据交给 4 个任务，每个任务都要求“读完全部记录”。结果全部改成关键词筛选。只写事件名、没写月份的内容，日历月写法（“九月（13月）”），早期旧帖的叫法，以及长评里夹的数值，都被漏掉了。第二轮补漏时又有 3 个任务自行改了读法。主会话的抽查只能发现写错的内容，发现不了漏写的内容。所以不能只靠提示词里的“必须读完”，必须有能用脚本核对的台账。

   - **总字数不超过约 15 万字：** 一个写作任务读全部分段，同时写台账（见下方“台账”），然后写攻略。
   - **超过约 15 万字，或要拆成多个文件：** 分两段做。
     1. 摘录任务：按分段平分，每个任务固定负责连续的几份（不超过约 15 万字）。它逐条读全文，把所有阶段的内容都摘进笔记，并写台账。用下方“摘录任务说明”。
     2. 主会话汇总台账，运行覆盖检查（见“主会话核对”）。有缺漏就退回同一个摘录任务补读，补齐后再往下走。
     3. 写作任务：每个范围一个任务，只读摘录笔记里标了这个范围的条目，需要上下文时按记录号回查分段。用下方“任务说明模板”，把“读取全部记录”换成“读取 data/notes/ 下所有笔记里标了 <范围> 的条目”。
   - 怎么启动子任务：
     - 每个子任务都从空白上下文开始，只给它下方的任务说明，不带主会话的聊天记录。
     - 子任务要能读写主会话的工作目录，不要放进隔离的副本里。
     - 后续修改发给同一个子任务，不要另开新的。
     - 用中档以上的模型，比如 Claude Sonnet。不要用小型本地模型，它们曾出现截断输入、丢内容和事实错误。
     - Claude Code 桌面版的写法：`mcp__ccd_session__start_session`，参数 `initiation: "user_asked"`、`context: "fresh"`、`model: "claude-sonnet-5-5"`、`use_worktree: false`；后续修改用 `SendMessage`。
   - 没有子任务功能时，主会话自己按同一份任务说明做：逐份读分段，每份读完就写台账；上下文被压缩后从台账最后一个记录号继续。超过约 15 万字时，同样先做摘录、跑覆盖检查，再写攻略。
   - 任务汇报里写了“只扫了关键词”“没逐字读”“自己重新切了分段”，就算没完成。按台账退回补读，不要接着交付。
5. **核对后交付。** 任务汇报只是线索。先运行台账和输出检查脚本，再亲自读输出文件，见“主会话核对”。

## 台账

每个读记录的任务都要写台账：`data/ledger/<任务名>.tsv`，制表符分隔，一条记录一行。

```text
id	状态	阶段	备注
33	用了	高一,高二	作者甲 时间线（上）
24	不相关		页面按钮
57	同人		
88	无攻略信息		纯感想
```

- 状态只能写四种：用了、不相关、同人、无攻略信息。“用了”要写阶段，多个阶段用逗号分隔。
- 每读完一份分段就追加这份的台账和笔记，再读下一份。上下文被压缩后，从台账里最后一个记录号继续。
- 长评、问答也要读完全文再判断状态，不能只看开头。

## 摘录任务说明

```text
你负责 <工作目录>/data/chunks/ 下的 <partAA.txt 到 partBB.txt>，按顺序逐份读完，每条记录读全文。不要用关键词筛选，不要自己重新切分，不要跳过长评和问答。

每读完一份分段，就做两件事，再读下一份：
1. 追加笔记到 data/notes/<任务名>.md。每条用到的记录写一节：
   ### #记录号 作者 日期
   - [阶段] [时间：原文写法，能推出累计时间的写推出值，推不出写“未写时间”] 内容（尽量用原文短句；数值、选项、条件照抄）
   阶段写 <阶段列表> 之一，或“通用”。
2. 追加台账到 data/ledger/<任务名>.tsv，格式见 data/台账说明.md。你负责的每一条记录都要有一行。

摘录规则：
- 只写原文有的内容，不概括成结论，不合并作者，不猜屏蔽字。
- 引号里的话必须能在原文里逐字找到。
- 否定和转折照抄（以为、没有、不能、不用、不够）。
- 只写事件名、不写时间的内容也要摘，时间写“未写时间”。日历月、学期、寒暑假、休假月等写法照抄。

汇报：读了哪几份、台账行数、各阶段摘了多少条、哪些记录拿不准阶段。
```

把台账格式（上面“台账”一节）存成 `data/台账说明.md`，让任务能读到。

## 任务说明模板

```text
读取 <记录文件> 的全部记录，把所有和 <范围> 有关的内容合并成一份时间线攻略，写到 <输出文件>。

读法：
- 记录已切成 <工作目录>/data/chunks/partNN.txt，按顺序逐份读全文。不要用关键词筛选，不要自己重新切分，不要跳过长评和问答。
- 每读完一份分段，就把这份的台账追加到 data/ledger/<任务名>.tsv（格式见 data/台账说明.md），再读下一份。上下文被压缩后，从台账最后一个记录号继续。
- 台账没覆盖全部记录前不要开始写攻略。写不完就如实汇报读到哪一份，不要改用关键词扫描来凑完。

来源：
- 只用原文。每个数值、操作和时间都必须能在记录里找到。
- 其他模型的输出、之前的摘要都不能当来源。
- 范围外的内容不写；只有它是范围内决策的直接原因时，才写一句。
- 记录里的 tags 只是提示，请自己复核。长评、同人默认不当来源，除非含具体可用的攻略信息；标了“提到改版”的、写得早的，或作者自己说已改版的内容，要在对应位置标注。

结构（用 Markdown 标题，定位工具按标题切分）：
1. 开头：范围、作者说明（作者的路线、版本或发布时间）。
2. ## 目标数值：不同路线分别列，标作者。
3. ## 开局（如果有开局选择）。
4. ## 每日通用选项：原文没写具体时间的做法放这里。
5. 按时间排列的节，标题写时间，节内按上午、下午、晚上、深夜等游戏里的时段分行。时间单位跟随来源，不要硬套“N月”：按周写“## 暑假第一周”，按月写“## 五月”，按事件节点写“## 华光奖前”。同一份里可以混用；节点之间的顺序必须注明依据（原文哪句话、哪个作者），没有依据就在文末说明顺序不确定。
   如果游戏不是按“N月”显示时间，在标题末尾用方括号写游戏屏幕上显示的文字作为定位关键词：
   - 年月制：“## 一月”“## 七月、八月”，不用方括号。但同一月份跨多年出现时（比如两个“四月”），要写带年份的关键词。写了关键词的节只按关键词定位，不再按月份匹配。
   - 周制等其他时钟：“## 暑假第一周 [第1周]”。
   - 多个关键词用竖线：“[第1周|第2周]”；连续范围写“[第4-8周]”。
   - 同样的周数还会跟在月份后面时，要把星期写进关键词，比如“[第1周周1|第1周周2|…|第1周周日]”，这样“9月 第1周”不会命中。不要用 `!月`，文字分开绘制时定位会来回跳。
   - 标题写时间范围时必须加关键词范围，比如“## 第8年到第18年 [修炼8-18年]”。不写的话只认首尾，中间年份定位不上。
   - 同一份攻略里，只要一节用了关键词，所有带时间的小节都要用关键词，并使用游戏实际显示的前缀，比如“修炼”。“第N年”可能和游戏纪年比不上。
   - 关键词默认这样推：屏幕格式 + 攻略里的时间。比如屏幕是“靖安成17年 3月”，攻略写十月，且前后时间能推出是16年，就写“[靖安成16年10月]”。原文没写年份时，从相邻节点往前后推算；别称先换算，比如冬月写 11月、腊月写 12月；显示可能有两种时写两个，比如“[靖安成17年1月|靖安成17年元月]”。
   - 大节写整年关键词，小节写年加月，比如“## 魏其王半年 [靖安成16年]”下面是“### 三月 [靖安成16年3月]”。这样年月拼接失败时大节还能定位。
   - 推断的关键词要在文末列出依据，并写明推错了只会定位不到，改方括号里的数字即可。只有连屏幕格式都不知道时才留空，并在汇报里列出待确认的标题。
6. ## 文末：答案、角色选项、原文没说清的地方。保持简短；各作者的路径不放这里，放在对应时段里。

每个时段的写法：
- 先写“推荐路径”：选一位作者的路径，或写一段简略总结，标明作者、适用条件和选择理由。它只是阅读入口，不替读者下结论。
- 紧接着在同一时段下写“其他路径”：保留所有作者的做法，一位作者一项，用二级列表，不移到文末，不用折叠标签。
- 推荐路径里已经写过的做法，在其他路径里仍然保留，方便按作者查。
- 长列表（如各作者的人气、数值）放在对应小节里，一项一行，不挤成一段。

合并规则：
- 不分路线章节。不同做法作为同一时段下的选项，写成“做法，效果（作者）”。
- 选项要写明适用条件，比如“有钱时”“无花”“要攻略角色”。同一时段互斥时要写清；不要写原文没有依据的“二选一”。
- 相同做法合并到一行，并列标作者。
- 数值不同时都写出来，如“精神 +30（甲）/ +20（乙）”。不要替读者选。
- 同一作者有新旧版本时，用年份区分，如“作者丙 2018”。
- 作者只写名字，不写记录编号，不用路线代号；提到作者时写“作者”或名字，不用“他”“她”。

时间归属：
- 原文明确属于某时间的，放在那个时间。
- 作者写“其他时间”的固定循环，可以放进除特殊时间点外的每一节，要标明“默认循环”。
- 原文没写时间的内容不要塞进某个时段，放到“每日通用选项”。
- 某时间没有内容就写“原文未提”，不要补。

容易出错的地方：
- 不要把不同数值的来源混在一起（例如“1 仙魂换名望”和“体质转寿命”是两回事）。
- “以为会触发”不等于“会触发”，注意否定和转折（以为、没有、不能、不用、不够、数不多）。
- 名称写法不同时都保留，不确定是否同一人就在文末说明。
- 屏蔽字保留原样，不要猜，也不要用人名替换（例如原文“**女儿”不能写成某个角色名）。
- 引号里的话必须能在原文里逐字找到；是概括就不加引号。并列多位作者时，每位作者都要在原文里写过。
- 开头的概括和作者说明最容易写错，写完要单独对照原文再读一遍。

写完后逐条对照原文核对，尤其是时间、时段和数值。不用表情符号。结构要让用户能边玩边看：推荐路径一眼能找到，其他路径在同一节里能定位。

汇报：输出路径、台账行数和读到的最后一份分段、用到了哪些记录、哪些内容因为没写时间放进了通用选项、顺序不确定的节点、互相矛盾的说法、哪些关键词是推断的。
```

## 主会话核对

交付前先跑两个脚本，再读输出文件并回到来源抽查。

**覆盖检查。** 先查有没有漏读，再查写错。抽查只能发现写错的内容，发现不了漏写的内容。

```bash
python -I -X utf8 <本技能目录>/scripts/check_coverage.py <records_clean.json> data/ledger/*.tsv \
  --guide 高一=<高一攻略.md> --stage 高一='高一|第?([1-9]|1[0-2])月(?!\d)'
```

- 缺号、重号、格式错的行：退回负责这些记录的任务补读，不要自己当作“不相关”补上。
- “用了但作者不在攻略里”：写作任务漏写了，退回写作任务补上。
- `--stage` 的复查列表：记录里出现这个阶段的词，台账却没归到这个阶段。逐条看，确实相关的退回补写。正则按本作的时间写法定，包括日历月、学期、寒暑假等别称。

**输出检查。**

```bash
python -I -X utf8 <本技能目录>/scripts/check_guide.py <records_clean.json> <攻略.md>...
```

它列出来源里搜不到的三位以上数字、不能逐字对上的引语（附 3 字片段重合率，低分多半是编的），以及数字不在该作者自己记录里的“做法（作者）”。列出来的都要回原文查，脚本只给线索。

然后人工核对：

- 通读开头的概括和作者说明，逐句对照来源。这里错误最集中，不能只抽查正文。
- 搜索来源里带屏蔽字（**、***）的句子，看攻略用到它们的地方有没有把屏蔽字换成人名。
- 搜索输出里的否定词（以为、没有、不能、不用、不够、数不多等），确认没有写反。
- 抽查并列作者的归属：几个作者并列的做法，来源里每位作者是否都写了。
- 随机抽至少 5 处数值或时间，在原文里搜到出处。
- 确认用户关心的作者都已覆盖；没用上的要说明原因。
- 确认作者说“其他时间”的内容才进了默认循环。
- 用扩展的 `splitGuideSections`、`findKeywords` 模拟游戏文字，每个时间范围都测首、中、尾，并测相近文字不会误命中，比如“修炼10年”不命中 `修炼1年`，“9月 第1周”不命中暑假小节。
- 确认所有带时间的小节都有关键词，推断的关键词在文末写了依据，并告诉用户这些没有在真实游戏里验证。
- 确认每个时段都有推荐路径，且所有作者的做法都在该时段的其他路径里，没有被推荐路径吃掉。

发现错误就直接修正，或发给同一任务修改。汇报时写明核对了哪些内容、哪些没有逐字校对，不要说“已全部校对”。台账没有覆盖全部记录时，要告诉用户缺了哪些记录，不要说“已读完”。

## 输出示例

